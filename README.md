# FAMBF — Клиентский калькулятор: защита капитала в USDT + участие в росте BTC

Брендированный калькулятор для разговора с клиентом. Один самодостаточный файл `index.html` — без сборки, без зависимостей, без бэкенда; открывается в любом браузере и работает на GitHub Pages. Считает на **реальных котировках опционов Deribit на 20.07.2026** (спот BTC $64 500, DVOL≈38, серии BTC-28AUG26 / 25SEP26 / 25DEC26) — котировки правятся прямо на странице.

Рядом лежит `calculator_advanced.html` — прежняя «инженерная» версия со всеми параметрами (волатильность, кэп/call-spread, произвольная защита), для внутренней работы.

## Как устроен (три шага клиента)

1. **Взнос** — сумма в USDT (по умолчанию 80 000; есть быстрые кнопки 10–250 тыс.).
2. **Срок × риск** — матрица: срок **~30 / ~90 / ~180 дней** (фактические серии Deribit BTC-28AUG26 · 39 дн, BTC-25SEP26 · 67 дн, BTC-25DEC26 · 158 дн) на допустимую просадку клиента **−2% / −3% / −5%** (защита 98/97/95%). В каждой ячейке — участие клиента в росте BTC при текущем распределении доходности и максимум по бюджету.
3. **Распределение доходности** — шкала **0–100%**, по умолчанию **100% клиенту**: весь опционный бюджет (за вычетом издержек исполнения 0,3%) идёт в участие клиента, а доход проекта — только комиссия входа 1%. Сдвинув ползунок, часть бюджета можно оставить проекту как фиксированную маржу (не зависит от BTC).

Дальше страница показывает: участие, максимальную просадку, маржу проекта (USDT, % за период и в годовых), резерв в надёжную ногу, котировку колла выбранной серии, таблицу «риск → доходность» (доход клиента при BTC +10/+30/+50%), график выплаты и сценарии −50%…+100% в USDT для введённого взноса.

**Живые котировки.** В блоке «Допущения» поля с марками ATM-коллов (5,20 / 7,25 / 11,95% от спота на 20.07.2026, калибровка по DVOL) и **днями до экспирации каждой серии** — оба редактируются, поэтому страница не устаревает: когда серия истекает, впишите новую (её дни и марку) — перед сделкой впишите mark price серии из терминала Deribit, всё пересчитается. Там же правятся спот, доходность USDT, буфер исполнения и комиссия входа.

## Живые данные Deribit и инфографика ожиданий

При каждом открытии страница сама обращается к **публичному API Deribit** (ключи не нужны): берёт спот-индекс BTC, список активных опционных серий и mark price ATM-коллов трёх серий, ближайших к 30 / 90 / 180 дням (серии короче 8 дней пропускаются). Обновляются спот, названия серий, дни до экспирации и марки; бейдж в разделе «Ожидания по пакетам» становится зелёным: **live · Deribit · дата и время**. Серии «перекатываются» сами: когда очередная истекает, страница автоматически берёт следующую — руками ничего менять не нужно.

Если API недоступен (нет сети, блокировка в браузере) — калькулятор молча работает на встроенных офлайн-марках от 20.07.2026, бейдж остаётся жёлтым. Всё по-прежнему можно править вручную в «Допущениях».

**Инфографика «Ожидания по пакетам»** — сравнение всех трёх пакетов на одном графике: столбики доходности клиента при BTC −20 / 0 / +10 / +30 / +50% за срок пакета, под каждым пакетом — выплата в USDT для взноса **10 000 / 100 000 / вашего** (переключатель), участие и точка безубытка. Учитываются выбранные риск (шаг 2) и доля клиента (шаг 3). Это иллюстрация выплатной формулы на текущих котировках, а не прогноз и не обещание доходности.

В каждой группе есть **янтарный столбик «мед.»** — выплата пакета при **медианном росте BTC за такой срок** по реальным данным 2021–17.06.2026 (61–66 скользящих окон, включая обвал 2022): 1 мес +1,4%, 2 мес +3,5%, 3 мес +2,1%, 6 мес +14,7%; для промежуточных сроков — интерполяция. Второй режим — **«Пакет vs BTC»**: выбранный в шаге 2 пакет против покупки BTC на ту же сумму, парами столбиков по шести сценариям (включая медиану), с выплатами в USDT под каждой парой. На одной картинке видно и защиту при обвале −20%, и её цену — долю роста, которую получает клиент.

Приоритет источников данных на странице: **live API Deribit → `market.json` (ежедневный снапшот) → офлайн-марки**; бейдж всегда честно показывает, что именно используется («live», «снапшот» или «офлайн-марки»).

### Вариант B — строгое ежедневное обновление (GitHub Action)

В архиве `fambf-daily-update.zip` три файла: `.github/workflows/market.yml` (запуск по крону в 06:10 UTC + кнопка ручного запуска), `scripts/fetch_market.mjs` (тянет марки с Deribit, ключи не нужны) и стартовый `market.json`. Установка: распакуйте архив и перетащите **всё содержимое вместе с папками** в окно Upload files репозитория (структура сохранится) → Commit. Затем вкладка **Actions** → при первом визите подтвердите включение workflows → откройте «market-data» → **Run workflow** (первый запуск вручную, дальше — сам раз в день). Теперь даже если браузер клиента не сможет достучаться до Deribit напрямую, страница покажет вчерашний снапшот, а не устаревшие цифры.

## Как опубликовать на GitHub Pages

1. Создайте репозиторий и загрузите в него `index.html` (и при желании этот `README.md`).
2. **Settings → Pages → Build and deployment → Source: Deploy from a branch.**
3. Выберите ветку `main` и папку `/ (root)`, нажмите **Save**.
4. Через минуту страница будет доступна по адресу `https://<ваш-логин>.github.io/<репозиторий>/`.
5. Эту ссылку можно передавать заказчикам — всё считается у них в браузере, ничего никуда не отправляется.

Альтернативно файл можно просто открыть локально (двойной клик) или разместить на любом статическом хостинге (Netlify, Cloudflare Pages, Vercel).

## Важно

Инструмент для оценки структуры продукта — **не котировка и не инвестиционная рекомендация**. Проценты участия зависят от рыночной волатильности и ставок на дату запуска и **не являются обещанием доходности**. Защита тела действует только на дату погашения и обеспечивается надёжной ногой и купленными опционами; её надёжность ограничена платёжеспособностью контрагентов и биржи, а также устойчивостью USDT. Любое предложение с обещанием возврата капитала может быть регулируемым продуктом — перед запуском требуется юридическая проверка лицензирования в соответствующей юрисдикции.
