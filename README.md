# HedgeUp — калькулятор вклада: защита капитала в USDT + участие в росте биткойна

Клиентская страница для разговора с инвестором. Один самодостаточный файл `index.html` — без сборки, зависимостей и бэкенда; работает на GitHub Pages и просто открытым файлом в браузере.

## Три шага клиента

1. **Сумма вклада** — поле ввода и быстрые кнопки (10 000 / 50 000 / 100 000 / 250 000 USDT).
2. **Срок размещения** — 30 / 60 / 90 / 180 дней. Под каждой кнопкой видна дата окончания и фактическое число дней: сроки исполняются ближайшими торгуемыми сериями опционов, поэтому «60 дней» может означать, например, 65 дней до 30.10.2026.
3. **Допустимый риск** — ползунок 1–10%: насколько вклад может уменьшиться в худшем случае. Чем выше риск, тем больше доля клиента в росте биткойна.

Дальше страница показывает три цифры (минимум к возврату, доля в росте биткойна, точка выхода в плюс), **кривую доходности** (вклад против «просто купить биткойн», с отметкой выхода в плюс), таблицу сценариев от −40% до +50% и короткую сводку словами.

## Откуда берутся котировки

Приоритет источников: **биржа Deribit (live) → ежедневный снапшот `market.json` → значения по умолчанию в файле**. При открытии страница сама запрашивает индекс BTC и mark price ATM-коллов по сериям, ближайшим к 30/60/90/180 дням, и обновляет спот, даты, число дней и цены опционов. Бейдж в шапке показывает актуальность: «котировки обновлены ДД.ММ.ГГГГ» (зелёный) или дата снапшота/дефолтных значений.

Все параметры (спот, доходность USDT, издержки, дни и цены опционов по каждому сроку) правятся вручную в свёрнутом блоке **«Параметры расчёта»** внизу страницы.

## Модель расчёта

- Сейф: `(1 − риск) × (1 + ставка USDT)^(−дни/365)` — к концу срока дорастает ровно до минимума к возврату.
- Бюджет на опционы: `взнос − сейф − издержки исполнения`.
- Покрытие: `min(1; бюджет ÷ цена опциона)` — не более одного опциона на весь взнос.
- Точка выхода в плюс: `риск ÷ покрытие`.
- Выплата: `минимум + покрытие × рост BTC`, за вычетом доли проекта в прибыли.

Доля проекта задаётся одной строкой в начале скрипта: `var SHARE=0.20;` — все цифры на странице показаны уже за её вычетом (клиент видит суммы на руки).

Если клиент уводит ползунок риска за полезную зону (покрытие уже 100%), под ползунком появляется предупреждение, что дальше увеличивать риск невыгодно.

## Публикация на GitHub Pages

1. Repository → **Add file → Upload files** → перетащите `index.html` (перезапишет предыдущую версию) → **Commit changes**.
2. Settings → Pages → Source: ветка `main`, папка `/ (root)` — если Pages ещё не включены.
3. Откройте `https://<логин>.github.io/<репозиторий>/` с жёстким обновлением (Ctrl/Cmd+Shift+R).

## Ежедневное обновление котировок (необязательно)

В архиве `fambf-daily-update.zip`: `.github/workflows/market.yml` (крон 06:10 UTC + ручной запуск), `scripts/fetch_market.mjs` (тянет марки с Deribit, ключи не нужны) и стартовый `market.json` на четыре срока. Распакуйте и загрузите содержимое вместе с папками, затем вкладка **Actions** → включить workflows → «market-data» → **Run workflow** один раз вручную. Дальше снапшот обновляется сам; страница использует его, если браузер клиента не может обратиться к бирже напрямую.

Если запуск падает с ошибкой прав при `git push`: Settings → Actions → General → Workflow permissions → **Read and write permissions** → Save → Re-run jobs.

## Логотип

Подтягивается с `https://fambf.com/assets/brand/logo-primary.svg`. Если он не отображается, логотип можно вшить прямо в файл (inline SVG или base64) — тогда страница перестаёт зависеть от внешнего адреса.

## Важно

Страница носит иллюстративный характер: не оферта, не котировка, не гарантия доходности. Защита вклада действует на дату окончания срока. Ключевые риски вне формул: надёжность биржи-контрагента, привязка USDT к доллару, качество размещения средств.
