# HedgeUp — калькулятор вклада: защита капитала в USDT + участие в росте биткойна

Клиентская страница для разговора с инвестором. Один самодостаточный файл `index.html` — без сборки, зависимостей и бэкенда; работает на GitHub Pages и просто открытым файлом в браузере.

## Что на странице

1. **Шаг 1 · Сумма вклада** — поле ввода и быстрые кнопки (10 000 / 50 000 / 100 000 / 250 000 USDT).
2. **Шаг 2 · Срок размещения** — 30 / 60 / 90 / 180 дней. Под каждой кнопкой видна дата окончания и фактическое число дней: сроки исполняются ближайшими торгуемыми сериями опционов, поэтому «60 дней» может означать, например, 65 дней до 30.10.2026.
3. **Шаг 3 · Допустимый риск** — ползунок 1–10% с шагом 0,5%: какой долей вклада клиент готов рискнуть. Именно она идёт на покупку опциона. Если риск уходит за полезную зону (покрытие упёрлось в 100%), под ползунком появляется предупреждение.
4. **Шаг 4 · Распределение прибыли от роста биткойна** — ползунок 0–100% в пользу проекта с шагом 0,5% (по умолчанию 5%), с наглядной полосой «клиент / проект». Делится только прибыль от роста BTC.
5. **Ползунок роста биткойна** (−50% … +100%, шаг 0,5%) — показывает результат вклада в процентах, сумму на руки и поясняющую строку под каждый случай.
6. **Две карточки** — минимум к возврату и доля клиента в росте биткойна.
7. **Кривая доходности** — вклад против «просто купить биткойн».
8. **Риск проекта** — сколько проекту нужно доложить в текущем сценарии, максимум риска и полная расшифровка с доходом проекта.

## Модель расчёта

Обозначения: `P` — вклад, `X` — допустимый риск клиента, `q` — цена ATM-колла в % от цены BTC, `slip` — издержки исполнения (0,3%), `y` — ставка надёжной ноги (10,8% годовых), `T` — срок в долях года, `R` — изменение цены BTC за срок, `s` — доля проекта в прибыли (шаг 4).

- **Тело клиента в сейфе:** `P × (1 − X)`. Доход сейфа за срок `P × (1 − X) × ((1+y)^T − 1)` — это **доход проекта**, клиент в нём не участвует.
- **На опционы идёт только доля риска:** `X − slip`. Покрытие `N = min(1; (X − slip) ÷ q)`.
- **Итог клиента:** при падении вклад повторяет биткойн, но не глубже лимита — `max(−X; R)`; при росте клиент получает свою долю с первого процента — `N × R × (1 − s)`.
- **Риск проекта:** `обещано клиенту − (тело в сейфе + выплата опционов)`, не меньше нуля. Максимум — когда биткойн вернулся к цене входа; ноль — когда биткойн упал на `X` и глубже (там просадку целиком несёт клиент).
- **Доход проекта:** комиссия входа 1% + доход сейфа + доля `s` от прибыли клиента.
- **Полезная зона риска:** `X ≤ q + slip` — дальше покрытие уже 100% и повышать риск клиенту невыгодно.

Значения по умолчанию задаются в объекте `S` в начале скрипта (`spot`, `yieldPct`, `slipPct`, `entryPct`, `days`, `dates`, `q`), стартовая доля проекта — в `var SHARE`.

## Откуда берутся котировки

Приоритет источников: **биржа Deribit (live) → ежедневный снапшот `market.json` → значения по умолчанию в файле**. При открытии страница сама запрашивает индекс BTC и mark price ATM-коллов по сериям, ближайшим к 30/60/90/180 дням, и обновляет спот, даты, число дней и цены опционов. Бейдж в шапке показывает актуальность: «котировки обновлены ДД.ММ.ГГГГ» (зелёный) либо дата снапшота / значений по умолчанию. Снапшот старого формата (три слота) страница игнорирует.

## Публикация на GitHub Pages

1. Repository → **Add file → Upload files** → перетащите `index.html` и `README.md` (перезапишут предыдущие) → **Commit changes**.
2. Settings → Pages → Source: ветка `main`, папка `/ (root)` — если Pages ещё не включены.
3. Откройте `https://<логин>.github.io/<репозиторий>/` с жёстким обновлением (Ctrl/Cmd+Shift+R) и проверьте бейдж в шапке.

## Ежедневное обновление котировок (запасной канал, необязательно)

В архиве `fambf-daily-update.zip`: `.github/workflows/market.yml` (крон 06:10 UTC + ручной запуск), `scripts/fetch_market.mjs` (тянет марки с Deribit, ключи не нужны) и стартовый `market.json` на четыре срока. Распакуйте и загрузите содержимое вместе с папками (в Finder скрытая папка `.github` показывается по Cmd+Shift+точка), затем вкладка **Actions** → включить workflows → «market-data» → **Run workflow** один раз вручную.

Нужен только на случай, если браузер клиента не может обратиться к бирже напрямую: тогда страница возьмёт вчерашний снапшот вместо зашитых значений. Если запуск падает с ошибкой прав при `git push`: Settings → Actions → General → Workflow permissions → **Read and write permissions** → Save → Re-run jobs.

## Логотип

Подтягивается с `https://fambf.com/assets/brand/logo-primary.svg`. Если он не отображается, логотип можно вшить прямо в файл (inline SVG или base64) — тогда страница перестаёт зависеть от внешнего адреса.

## Важно

Страница носит иллюстративный характер: не оферта, не котировка, не гарантия доходности. Защита вклада действует на дату окончания срока. Ключевые риски вне формул: надёжность биржи-контрагента, привязка USDT к доллару, качество размещения средств.
