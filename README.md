# HedgeUp — калькулятор вклада: защита капитала в USDT + участие в росте биткойна

Клиентская страница для разговора с инвестором. Один самодостаточный файл `index.html` — без сборки, зависимостей и бэкенда; работает на GitHub Pages и просто открытым файлом в браузере.

## Что на странице

1. **Шаг 1 · Сумма вклада** — поле ввода и быстрые кнопки (10 000 / 50 000 / 100 000 / 250 000 USDT).
2. **Шаг 2 · Срок размещения** — 30 / 60 / 90 / 180 дней. Под каждой кнопкой видна дата окончания и фактическое число дней: сроки исполняются ближайшими торгуемыми сериями опционов, поэтому «60 дней» может означать, например, 65 дней до 30.10.2026.
3. **Шаг 3 · Допустимый риск** — ползунок 1–10% с шагом 0,5%: насколько вклад может уменьшиться в худшем случае. Если риск уходит за полезную зону (покрытие уже 100%), под ползунком появляется предупреждение.
4. **Ползунок роста биткойна** (−50% … +100%) — показывает результат вклада в процентах, сумму на руки и поясняющую строку: защита при падении, «роста пока не хватает» внутри коридора, доля клиента в прибыли после выхода в плюс.
5. **Две карточки** — минимум к возврату и доля клиента в росте биткойна.
6. **Кривая доходности** — вклад против «просто купить биткойн», с отметкой минимума.
7. **Риск проекта** — коридор от 0% до выхода клиента в плюс, в процентах и деньгах (см. ниже).

## Модель расчёта

- Сейф: `(1 − риск) × (1 + ставка USDT)^(−дни/365)` — к концу срока дорастает ровно до минимума к возврату.
- Бюджет на опционы: `взнос − сейф − издержки исполнения`.
- Покрытие: `min(1; бюджет ÷ цена опциона)` — не более одного опциона на весь взнос.
- Точка выхода в плюс: `риск ÷ покрытие` (числом на странице не показывается — клиент нащупывает её ползунком роста).
- Выплата клиенту: `минимум + покрытие × рост BTC`, за вычетом доли проекта в прибыли.
- **Риск проекта** считается только в коридоре роста: цена BTC на дату расчёта выше цены входа, но ниже безубытка клиента. Формула: `разрыв клиента до вклада − доход надёжной ноги за срок`, никогда не отрицательный. При падении и нулевом изменении BTC риск равен нулю — просадку покрывает сам клиент. Комиссия входа 1% в расчёт не включена.

Доля проекта в прибыли клиента задаётся одной строкой в начале скрипта: `var SHARE=0.05;` (сейчас клиенту 95%, проекту 5%). Все суммы на странице показаны уже за её вычетом.

## Откуда берутся котировки

Приоритет источников: **биржа Deribit (live) → ежедневный снапшот `market.json` → значения по умолчанию в файле**. При открытии страница сама запрашивает индекс BTC и mark price ATM-коллов по сериям, ближайшим к 30/60/90/180 дням, и обновляет спот, даты, число дней и цены опционов. Бейдж в шапке показывает актуальность: «котировки обновлены ДД.ММ.ГГГГ» (зелёный) или дата снапшота / дефолтных значений.

Ручного блока параметров на странице нет — значения по умолчанию правятся в коде (объект `S` в начале скрипта: `spot`, `yieldPct`, `slipPct`, `days`, `dates`, `q`).

## Публикация на GitHub Pages

1. Repository → **Add file → Upload files** → перетащите `index.html` и `README.md` (перезапишут предыдущие) → **Commit changes**.
2. Settings → Pages → Source: ветка `main`, папка `/ (root)` — если Pages ещё не включены.
3. Откройте `https://<логин>.github.io/<репозиторий>/` с жёстким обновлением (Ctrl/Cmd+Shift+R) и проверьте бейдж в шапке.

## Ежедневное обновление котировок (запасной канал, необязательно)

В архиве `fambf-daily-update.zip`: `.github/workflows/market.yml` (крон 06:10 UTC + ручной запуск), `scripts/fetch_market.mjs` (тянет марки с Deribit, ключи не нужны) и стартовый `market.json` на четыре срока. Распакуйте и загрузите содержимое вместе с папками (в Finder скрытая папка `.github` показывается по Cmd+Shift+точка), затем вкладка **Actions** → включить workflows → «market-data» → **Run workflow** один раз вручную.

Нужен только на случай, если браузер клиента не может обратиться к бирже напрямую: тогда страница возьмёт вчерашний снапшот вместо зашитых значений. Снапшот старого формата (три слота) страница игнорирует и работает по live-данным.

Если запуск падает с ошибкой прав при `git push`: Settings → Actions → General → Workflow permissions → **Read and write permissions** → Save → Re-run jobs.

## Логотип

Подтягивается с `https://fambf.com/assets/brand/logo-primary.svg`. Если он не отображается, логотип можно вшить прямо в файл (inline SVG или base64) — тогда страница перестаёт зависеть от внешнего адреса.

## Важно

Страница носит иллюстративный характер: не оферта, не котировка, не гарантия доходности. Защита вклада действует на дату окончания срока. Ключевые риски вне формул: надёжность биржи-контрагента, привязка USDT к доллару, качество размещения средств.
